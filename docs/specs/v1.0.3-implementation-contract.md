## 0. 通用约定

- 所有运行包 Python 脚本只用标准库；CLI 统一 `--input/--output`（或明确的子命令），
  输出文件用 `open("x")` 排他创建，绝不覆盖；输出路径不得位于运行包内（沿用
  `render_deep_equity_research.py` 的 `_write_new` 约定与 "File exists"/
  "Skill runtime package" 错误语义）。
- 错误以非零退出 + stderr 单行说明失败关闭；数据不足时在 JSON/Markdown 中写
  `status: "missing_inputs"` / `not_applicable` + 原因，不伪造数字。
- 所有金额字段携带 `currency`；所有时间戳为带时区 ISO-8601；来源对象统一为
  `{"name", "kind", "as_of", "url"}`，`kind` 沿用既有枚举
  （`sec_filing/regulatory_filing/issuer_ir/exchange/issuer_announcement/credible_media/public_quote/valuation_assumption`）。
- 所有 artifact 携带身份块：

```json
"identity": {"issuer_id": "...", "listing_id": "...", "case_id": "...",
             "artifact_version": 1, "schema_version": 1}
```

  A/H 对比共用一个 `case_id`、两个 `listing_id`。裸 ticker 不是主键。
- 每个可复算 artifact 记录 `engine`（脚本路径）、`engine_version`、`model_version` 或
  `rules_version`、`computed_as_of`。
- 交易指令词守卫沿用现有 `TRADE_DIRECTIVE` 正则（买入/卖出/加减仓等）；
  交易方案只允许条件式词汇：入场区间、目标区间、失效条件、观察/等待。

## 2. Batch 1：市场偏好 `scripts/market_preferences.py`

偏好文件：活动工作目录下用户可见的 `mars-market-preferences.json`：

```json
{
  "schema_version": 1,
  "enabled_market_scopes": ["us", "hk", "a_share", "ah_compare"],
  "default_market_scope": "us",
  "updated_as_of": "2026-08-01T00:00:00+08:00",
  "note": "每台设备本地保存；只有用户明确导入/同步时才跟随 Drive。"
}
```

- `enabled_market_scopes` 多选，取值 `us/hk/a_share/ah_compare`；选 `ah_compare`
  自动蕴含 `hk` 与 `a_share` 基础范围（写入时自动补齐并记录）。
- `default_market_scope` 可空；仅用于未指定市场的宽泛请求；**未设置偏好时不得默认美股**。

CLI 子命令（输出 JSON 到 stdout，`--workspace` 指定工作目录，默认 cwd）：

- `show`：打印当前偏好；文件不存在时输出 `{"status": "onboarding_required"}`。
- `set --scopes us,hk[,a_share,ah_compare] [--default us]`：写入/更新偏好（允许覆盖
  偏好文件本身——它是用户可编辑状态，不是研究 artifact）。
- `resolve --query 0700.HK|700|600519|Apple [--once-scope hk]`：解析市场范围，输出：

```json
{"status": "resolved", "market_scope": "hk", "listing_candidates": [...], "reason": "explicit_suffix"}
{"status": "ambiguous", "candidates": [{"market_scope": "hk", ...}, {"market_scope": "a_share", ...}], "reason": "bare_code_multiple_matches"}
{"status": "onboarding_required"}
{"status": "out_of_scope", "market_scope": "us", "options": ["once", "add_to_scope"]}
```

解析规则：

1. 显式后缀优先：`.HK→hk`；`.SS/.SH/.SZ→a_share`；`.US` 或无后缀纯字母→`us`。
2. 裸数字代码：`6` 开头 6 位→上交所；`0/3` 开头 6 位→深交所；1–5 位数字→港交所。
   若匹配到的市场包含多个**已启用**范围候选（如 `ah_compare` 同时启用 hk+a_share
   时裸 6 位代码仅属 a_share，不歧义；纯字母名称多发行人同名时才歧义）→ `ambiguous`，必须询问。
3. 解析结果不在 `enabled_market_scopes` → `out_of_scope`，提供“仅本次使用 /
   加入我的市场范围”两个选项，不自动启用。
4. 偏好文件不存在 → `onboarding_required`；`--once-scope` 只对当次生效，不写盘。
5. A/H 配对：`resolve --ah-pair 600519.SS,0700.HK` 校验两个 listing、币种
   （CNY/HKD）、并输出 `pair_status`，无法唯一配对时 `failed` + 原因。

中文公司名不做本地猜测：返回 `ambiguous`/`needs_user_selection`，由上层询问。


硬性规则：

- 概率必须显式输入、三情景各一、合计 1±1e-6，并带 `rationale`；概率≠置信度。
- 终值三查：① 永续增长率 ≤ `long_run_growth_cap`；② 终值隐含成熟利润率与
  `mature_margin_benchmark` 对照；③ 再投资率 ≈ g/ROIC 与隐含 FCF 一致性。
  三项结果全部留档，`fail` 不阻止计算但必须在 `data_gaps`/结论中显式标注。
- 缺少任何必要输入 → 该模型 `status: "missing_inputs"` + `missing: [...]`，
  **不输出公允价值数字**。
- PE 情景必须为三个唯一情景，概率合计为 1±1e-6；`eps` 与 `pe_multiple` 均须为正，
  且 `earnings_basis` 与 `basis_rationale` 必须显式记录。非正 EPS 应标为
  `not_applicable` 或 `invalid_inputs`，不得输出伪造的 P/E 目标。
- PE 的 `quality.status=usable` 要求价格、EPS、倍数、概率及来源完整且未超过来源时效；
  trailing EPS 未完成一次性项目和盈利可持续性复核时最多为 `conditional`，不能形成基本面目标。
- 反向 DCF 无解 → `no_solution`，沿用 v1.0.2 的区间语义。
- 蒙特卡洛用 `random.Random(seed)`，seed 与 trials 留档，保证可复算。
- `value_zone` = 概率加权值与保守情景（bear）每股价值构成的区间，供交易方案
  价值带使用；安全边际由交易方案层按预注册规则施加，不在引擎内拍脑袋。

### 3.1 通用驱动型 DCF（`models.dcf.driver_model` → `results.driver_dcf`）

成长股并非不能用 DCF，但单点、五年 FCF 加终值的旧三情景 DCF 不适合直接形成
精确目标价：旧 `results.dcf` 只折现手工给定的 `scenario.free_cash_flows`
（`scenario.margins` 仅供终值检查，并不驱动现金流），自 v1.0.3 起保留为
可审计 baseline（结果带 `model_role: "baseline"`），不再单独具备形成
“基本面目标/参考价值区间”的资格。`models.dcf` 下新增**可选、通用**的
`driver_model`（不含任何标的专属分支、参数或贴近市价的调参），现金流由经营
驱动逐年推导：

```json
"driver_model": {
  "scenarios": [
    {"name": "...", "probability": {"value": 0.5, "rationale": "..."},
     "forecast_periods": 5,
     "revenue": [...], "operating_margin": [...], "tax_rate": [...],
     "depreciation_amortization": [...], "capex": [...], "change_in_nwc": [...],
     "reinvestment_rate": {"value": ...}, "roic": {"value": ...},
     "source": {...}}
  ]
}
```

- 每个情景六个驱动数组长度必须等于 `forecast_periods`（整数，1–30），全部
  有限数值；`revenue` 非负、`operating_margin ∈ [-1, 1]`、`tax_rate ∈ [0, 1)`；
  概率 ∈ [0, 1] 且合计 1±1e-6 并带 `rationale`；情景名唯一（不要求
  bear/base/bull）。缺失字段 → `missing_inputs`；长度不一致、非数值/非有限、
  非法 `forecast_periods` → 直接拒绝（fail closed）；区间越界 →
  `invalid_inputs`。`reinvestment_rate` 与 `roic` 也是必需输入；缺失时同样返回
  `missing_inputs`，不得用隐含值补齐。**不静默补零、不猜数字。**
- 公式：`NOPAT_t = revenue_t × operating_margin_t × (1 − tax_rate_t)`；
  `FCF_t = NOPAT_t + D&A_t − capex_t − ΔNWC_t`；EV/equity/per_share 复用与
  baseline 相同的折现与 Gordon 终值（WACC、`terminal_growth`、净债务、股本
  共享自 `models.dcf`）。
- 高增长/过渡/稳定三阶段由逐年显式驱动路径表达（收入增速与利润率的 fade
  直接写进数组）；完整三阶段闭式解不在本契约内。终值假设
  （`terminal_assumptions`）、每情景 `terminal_value` 及其占 EV 比例、
  ROIC/再投资一致性（沿用终值三查，成熟利润率对照取终值年
  `operating_margin`）全部记录在结果中。**严禁为贴近市场价格反向调整
  WACC、g、FCF 或概率。**
- 输出 `results.driver_dcf`：`model_kind`/`model_version`、`status`、
  `scenarios`（输入驱动 + 推导 `nopat_path`/`free_cash_flows` + EV/equity/
  per_share）、`probability_weighted_per_share`、`value_zone`（最低情景每股至
  概率加权值）、`terminal_value_checks`、`terminal_assumptions`、`quality`、
  `inputs_provenance`。
- 通用质量门槛 `quality.status`（与任何特定标的无关）：
  - `usable`：计算完成、终值三查全部 pass、各情景终值年 FCF 为正、概率加权
    每股为正、显式预测期 ≥ 5 年、情景与关键输入（股本/净债务）来源齐全且
    as_of 距 `computed_as_of` 不超过 400 天。**只有 usable 才有资格形成
    “基本面目标/定制 DCF 参考值”。**
  - `conditional`：计算完成但存在 warn 级终值检查、预测期 < 5 年、情景缺
    来源、情景来源或股本/净债务来源缺失或过时之一 → 报告只能标注“条件性模型输出”，
    未形成基本面目标。
  - `unreliable`：未完成计算、任一终值检查 fail、任一情景终值年 FCF 非正或
    概率加权每股非正 → “估值模型待重建”，输出仅为留档。
  - `quality.reasons`/`quality.flags` 逐条留档；非 usable 时写入
    `data_gaps`。
- 交易方案层（trade_plan）：`results.driver_dcf` 存在时，只有 quality 为
  usable 才以其 `value_zone`/概率加权值作为价值带与
  `fundamental_target`（basis=`driver_dcf`）；存在但未达 usable → 不形成
  基本面目标（value_source 为空，估值门不通过），**不回退到 baseline
  DCF**。未提供 `driver_model` 的旧输入行为完全不变（兼容冻结）。

## 4. Batch 4：财报质量 `skills/deep-equity-research/scripts/earnings_quality.py`

规则文件 `reference/earnings_quality_rules.json`（`rules_version` 版本化）：
阈值、权重、红旗清单、适用性门条件，全部可见可复核。

CLI：`--input earnings-quality-inputs.json --output earnings-quality.json`。

输入：`identity`、`market_scope`、`accounting_periods`（≥3 年年度 + ≥8 季度基线
字段；不足时对应组件记 `missing`）、`components`：

- `accruals`：net_income / operating_cash_flow / total_assets 序列（年度）。
- `beneish`：DSRI/GMI/AQI/SGI/DEPI/SGAI/LVGI/TATA 八变量所需原始字段（两年可比
  资产负债表+利润表）；适用性门：字段齐备且会计口径可比，否则 `not_applicable`。
- `revenue_recognition`：红旗布尔/数值项（应收账款增速 vs 收入增速、递延收入变化、
  关联方收入占比、期末突击收入迹象等），每项带来源。
- `cash_flow`：经营现金流/净利润比率、FCF 持续性。
- `audit_governance`：审计意见类型、审计师变更、内部控制缺陷、治理红旗，带来源。

输出 `earnings-quality.json`：

```json
{
  "identity": {...}, "rules_version": "v1.0.3-eq-1", "computed_as_of": "...",
  "grade": "A|B|C|D", "provisional": false,
  "long_entry_veto": false,
  "components": {
    "accruals": {"status": "computed|missing", "score": ..., "evidence": [...]},
    "beneish": {"status": "computed|not_applicable|missing",
                "m_score": ..., "variables": {...}, "threshold": -1.78},
    "revenue_recognition": {"status": "...", "red_flags": [...]},
    "cash_flow": {"status": "...", "evidence": [...]},
    "audit_governance": {"status": "...", "signals": [...]}
  },
  "data_gaps": [...]
}
```

- 组件缺失 → `provisional: true`（暂定级别），级别仍为 A–D 但必须标注暂定；
  缺数据不得伪装成确定结论。
- C 或 D → `long_entry_veto: true`，交易方案层确定性否决多头 `entry_plan`；
  任何情况下不输出做空建议。

决策门（全部确定性的，规则版本留档，研究完成后不改阈值）：

1. 任一 gate 不通过 → `status: "watch"`，`veto` 写明原因，只输出观察/等待条件，
   不输出可执行价格区间。此处禁止的是可执行交易价位（入场区间、技术/基本面
   目标、失效价位）与 `trade-plan.html`；呈现层（如 `underwriting.html` 摘要卡）
   可以原样展示估值 artifact 中已计算的非行动性参考值，但必须遵守估值模型的
   适用性标签：baseline DCF 只能作为可审计留档，driver DCF 只有 `usable` 才能
   标为定制参考值；`conditional`/`unreliable` 不得标注为交易目标或基本面锚，
   也不得在呈现层重算或构造新范围。
2. 财报质量 `long_entry_veto` → gate `earnings_quality` 失败。
3. 技术证据 `status != "qualified"` 或 `as_of` 早于
   `computed_as_of - technical_evidence_max_age_days` → gate 失败。
4. 价值区间（`valuation.value_zone` 施加 `safety_margin` 后）与技术支撑区
   （最近支撑 ± `entry_atr_tolerance`×ATR14）无交集 → gate 失败（无交集）。
5. `reward_risk_ratio < min_reward_risk_ratio` → watch。
6. 目标区间：技术目标 = 最近阻力位；基本面目标按估值来源资格确定：提供
   `driver_model` 且质量为 `usable` 时取驱动型 DCF 概率加权值；未提供
   `driver_model` 时为保持旧输入兼容，沿用既有概率加权适用模型；已提供但未达
   `usable` 时不形成基本面目标。技术目标与基本面目标始终分别标注，不混作一个数字。
7. 失效区间：技术失效 = 入场参考支撑 − `invalidation_atr_multiple`×ATR14；
   命题失效 = thesis 的可证伪条件。

`--html` 仅当 `status == "entry_plan"` 时生成 `trade-plan.html`：单文件、复用技术证据
OHLCV（不重新取数）、叠加价值带/入场带/失效线/目标带与标签；图上不创造新价位。
否则不生成并说明原因。
