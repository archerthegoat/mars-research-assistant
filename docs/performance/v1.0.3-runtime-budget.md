# v1.0.3 运行包预算基线

> 状态：发布前验收记录。v1.0.3 目标规格第 12 节要求重新制定 v1.0.2 的包大小与文件数
> 验证基线；本文记录新基线、理由与发布前实测，不涉及发布动作。

## 新基线

| 指标 | v1.0.2 基线 | v1.0.3 基线 | 当前实测 |
| --- | --- | --- | --- |
| 运行包文件数 | ≤ 60 | ≤ 80 | 50 |
| 运行包总大小 | ≤ 1 MiB | ≤ 1.5 MiB | 778,958 字节（≈0.74 MiB） |
| 个股快览 fixture 渲染 | ≤ 1 s | ≤ 1 s | ≈0.04 s |
| 深度研究 fixture 渲染 | ≤ 1 s | ≤ 1 s（承保渲染） | ≈0.05 s |

## 理由

- v1.0.3 新增独立 `investment-analysis` skill（4 个文件）、深度研究五个可测试脚本
  （dcf / earnings_quality / trade_plan / render_underwriting / providers）、四个版本化
  参考配置（行业注册表、市场合同、预注册规则、财报质量规则）、一个市场偏好脚本和一个
  Drive 工作台本地模拟脚本，同时删除 v1.0.2 的旧深度渲染器；净增约 15 个文件。
- 文件数预算按“当前 50 + 约 60% 余量”取 80；大小预算按“当前 ≈0.74 MiB + 约 100%
  余量”取 1.5 MiB，Lightweight Charts vendor（≈208 KB）仍占最大单块。
- 渲染性能预算不变：每个离线 fixture ≤ 1 秒，远低于预算的实测值表明新渲染链路
  （含内嵌估值/财报质量/交易方案 artifact 的展示）没有引入性能回归。
- 蒙特卡洛等较重计算只产生 JSON（毫秒级），不在 fixture 渲染路径上；估值引擎、财报
  质量与交易方案的端到端计算由各自 unittest 覆盖。
