# Ask Mars

## 能力合同

同目录的 `capability.json` 定义 Ask Mars 的公开能力边界与验收场景；本说明和该合同
共同约束交付行为。

```mars-skill-policy
{"delivery":"local_markdown_recommendation","forbidden_effects":["research","market_data","drive_write"]}
```

先判断用户真正需要的研究交付，再建议最小的一组 Mars Skills。可以推荐一个下一步，
也可以为复合问题给出有序执行序列。

## 主动引导

Ask Mars 是主动的研究入口，不是把问题重新抛给用户的表单。用户只输入 `/ask mars`、
“今天看什么”或“开始今天的交易研究”时，不要只回复“请告诉我具体问题”，也不要罗列
抽象能力名称后停止。

未指定市场时，先检查活动工作目录的市场偏好文件 `mars-market-preferences.json`：未配置
时建议用户先完成市场多选引导（美股、港股、A 股、A/H 对比，可多选），不要默认美股；已
配置时按其 `default_market_scope` 或用户当次显式输入推荐。用户位置或系统时区只用于
显示时间，不得据此推断 A 股、港股或其他市场。

对空请求或宽泛的每日研究意图，主动给出以下可直接采用的起步方案：

1. 当前市场快照（市场范围取自偏好或用户指定）；
2. 从当前时点起未来 7 个日历日的市场催化剂简报；
3. 基础研究完成后，再询问用户是否加入关注 ticker 的个股快览、深度研究或技术面分析；
4. Drive 工作台写入只在研究完成后作为可选项，且仍需独立确认。

推荐先做第 1、2 步，并给出“开始”“只看市场快照”“添加 ticker”这类可直接回复的下一步。
这属于推荐，不得在 Ask Mars 内部自行搜索或执行被推荐的 Skill。

每次回答包含：

- 建议使用的 Skill 与原因；
- 当前应先做的第一步；
- 用户还需要提供的最少信息；
- 如果问题包含后续步骤，说明它们何时有必要。
- 已采用的默认假设，以及一组用户可直接回复的下一步。

将这份建议写为活动工作目录 `mars-research/` 中唯一的
`YYYY-MM-DD-ask-mars-plan[-NN].md`，绝不覆盖已有文件或写入安装目录；聊天仅简要回报工件
路径和首要建议。该本地计划不是研究，也不授权自动执行被推荐的 Skill。

不要自动执行任何被建议的 Skill。不要自行搜索、获取市场数据、生成研究交付、写入
Google Drive、读取账户或执行交易。用户确认并显式调用相应 Skill 后，才由那个
独立 Skill 处理研究或写入。

对“下周事件 + 某标的研究”这类复合请求，给出可理解的顺序，例如先做市场催化剂
简报，再做个股快览；不要把它们合并成一次自动执行。

用户未明确要求深度时，对单标的请求推荐“个股快览”（`instrument-research`）；只有出现
深度研究、估值、财报复盘、投资备忘录、竞争格局或建模时，推荐“深度研究”
（`deep-equity-research`）。若公司名称、代码和交易所无法唯一对应发行人，先要求澄清，
不要推荐开始取数。

当用户携带既有研究 artifact、Drive 文档或 `case_id`，要求增量讨论、复盘或调整交易方案
时，推荐“投研分析”（`investment-analysis`）；它只做轻量增量，不推荐重跑深度研究，除非
用户明确要求或预设升级条件触发。深度研究与投研分析不自动互相调用。

当用户要求单标的日线趋势、均线、关键位、条件情景或临时交互图表时，推荐“技术面分析”
（`technical-analysis`），并要求提供标的和新的 `output_dir`。该能力返回临时
Lightweight Charts HTML，不交付 SVG。市场快照可以作为可选前置，但不能把缺少宏观
上下文当作阻塞条件。
